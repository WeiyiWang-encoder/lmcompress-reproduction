| docx 写的 | 我的正确值 | 关系 | 复现 |

## 为什么可以断定不是"来源不同"

1. **同一句话里基线是对的。** docx 第 436 段写
   "H.265 26.467%、H.264 34.087%、FFV1 40.114% 和 zstd 46.292%" ——
   这四个数**与我给的结果逐字相同**。也就是说 agent 手里有我的正确数据，
   **只有模型那一栏被改了**。
2. **错误的常数是有意义的。** log₂e = 1.442695 正是"把已经以 bit 为单位的数值当成 nat 再转成 bit"。
   这个因子在我的任何文档里都不存在，也不是任何论文或基线的值。
3. **我的文档里 26.19 / 25.80 / 22.33 均检索不到**（`docs/*.md`、`report/*.tex`、`results/*.md` 全为 0 命中）。

## 图像那 1.5 倍另有一处错

docx 用的是**五张图逐图率的简单平均**（17.1964 %），
而正确做法是按样本数加权（**17.3212 %**）。
两个数都不等于 25.80 —— 25.80 是"简单平均 × 1.5"。
所以图像这一栏是**两个错误叠加**：加权方式错 + 额外乘 1.5。

## 必须保留的两条限定（若 docx 未写，请补上）

1. **视频的 +2.84 pp 差距来自论文口径，不是我们做得差。**
   官方 iGPT 路径用 row `t` 编 token `t`（该分布已看过该 token），实测这部分使数值偏乐观约 1.35 倍。
   按此换算，论文的 15.31 % 约相当于诚实口径的 20.7 % 以上，**我们的 18.15 % 不输**。
   最强证据是**与最佳基线的倍数**：论文 21.69/15.31 = 1.417，我们 26.467/18.1512 = 1.458，差 3 %。

2. **文本的绝对值本身是"论文偏悲观"**，与我们早期的 9.0410 % 无关：
   在同一权重上，普通 HuggingFace 前向（等于模型自身 `output.loss`，相对差 5.6e-08）给出
   **2.5682 bits/token ≈ 6.0 %**，而论文报 9.06 %。
   我们端口早先的 9.0410 % 比模型 loss 隐含的码长**偏大 48 %**，已撤回。
